Introduction

What is KUONIX?

  • Desktop app for image classification and editing workflows.
  • Image analysis research drives the classification logic.
  • Local file & OS access built directly into the product.
  • Removes the selection step so editors focus on editing.

Frontend

Why we used Electron.

  • Cross-platform development from one frontend codebase.
  • Local file system access for importing image folders.
  • Native menus & notifications for a real editing workflow.
  • Desktop fit rather than a browser-only application.

Key message

  • Cross-platform reach from a single codebase.
  • OS-level access the product actually needs.

Backend

Why we used Spring Boot.

  • Multithreading for long-running, compute-heavy tasks.
  • Background processing keeps work off the UI path.
  • Responsive UI stays usable during heavy processing.
  • Service structure for organising the backend cleanly.

Processing flow

1. User action An analysis request starts from the desktop interface.
2. Background execution Spring Boot handles the work in the background.
3. Responsive UI The interface stays usable while processing completes.

Challenges

Main constraints we had to work through.

Repository limits Bitbucket storage limits forced a migration to GitHub.
Remote collaboration Remote work made real-time decisions harder to coordinate.
AI implementation cost A full AI approach exceeded our compute and budget.
Image classification difficulty Classification at scale is expensive with naive AI options.

AI Direction

Why we did not ship a full external AI model approach.

Option 1: Train our own model

  • Heavy compute required to train and iterate.
  • Higher infra complexity across the stack.
  • Not realistic for our available resources.

Option 2: Use external model APIs

  • High recurring cost on image classification APIs.
  • Scales aggressively with image volume.
  • Not sustainable at the volume we expect.

What we built instead

  • Studied research on image classification.
  • Drafted a clean algorithm around the problem.
  • Built a practical model without the full AI cost.

Outcomes

What we achieved.

Desktop-ready workflow

Electron gave us the right environment for file-heavy editing.

Responsive processing

Spring Boot kept heavy work off the UI thread.

Repository stability

GitHub removed the Bitbucket storage constraint.

Practical classification path

Research turned into a clean, resource-fit algorithm.
